# Implemented architecture

Each subsystem has an `index.ts` boundary. The browser and Electron share the Tiptap renderer. `src/browser` supplies same-origin HTTP transport and durable browser drafts. Electron main supplies native authentication, SQLite drafts and a narrow preload; its sandboxed renderer has no Node or network access. Explicit development mode uses a loopback Lobby bridge and its own Ablo project. Main verifies the sender frame and denies navigation, webviews and permissions.

## Authority and trust

`src/auth/native.ts` uses Coding's existing Ablo Electron protocol: native creates an S256 verifier and state, opens Forum's desktop Google handoff page, and exchanges a one-use code returned to `com.ablo.forum://auth/callback`. Callback scheme, host, path, state and a five-minute expiry are checked; the verifier is consumed before exchange. Email sign-in calls Ablo's existing OTP endpoints. Forum verifies workspace membership before saving the resulting session encrypted with Electron safeStorage. The renderer receives display state and sign-in/out actions, never a token. Sign-out cancels login, clears the encrypted session, closes the account's draft database, reloads windows, and revokes the native issuer session. Account-generation checks reject late responses from a previous identity. The shared Auth service must explicitly trust the Forum HTTPS origin and native scheme; no wildcard trust is used.

`src/hosted/index.ts` verifies native bearer sessions or the browser's existing HttpOnly Ablo cookie through hosted Ablo Auth. Only production Ablo session cookies are forwarded; unrelated cookies and staging sessions are excluded. Cookie requests require the exact Forum Origin; foreign, missing and sibling origins cannot authorize cookie RPC. Browser-origin bearer requests remain refused. The bounded identity lease lasts at most five seconds including verification time and fails closed after expiry. Workspace headers must match the issuer's organization. A session without an active organization must prove membership in a listed team, as in Coding. Browser sign-out calls the shared issuer and revokes that browser session across Ablo products. No credential is returned to browser JavaScript. Malformed and oversized requests are rejected; upstream errors never expose credentials or stacks.

`src/ablo/schema.ts` declares documents, accepted ProseMirror steps, idempotency receipts, conversation messages and agent runs. The hosted API alone holds the project credential and mints scoped Ablo actor sessions. Each workspace authority filters document lists by the verified organization and checks that organization before every document/history/metadata/chat action. Children are reachable only through an authorized document. This preview shares documents with all members of the selected organization; document-specific roles and invitations are not implemented.

Development mode is explicit: `ABLO_API_KEY` selects the developer’s project/branch, with no account-auth claim. The loopback bridge uses a random launch capability, rejects browser origins and insecure remote sockets, and bounds connections, admitted requests, payloads and buffered output. Human and agent grants permit only required Forum model operations; agents cannot create documents. A fresh model subprocess receives only a short-lived loopback MCP token and its dedicated model profile, never the project key. Its tool adapter fixes the document ID. There is no alternate SQLite document authority or production mock fallback.

## Text commits and recovery

Rich-text merging uses ProseMirror OT. A submit reads the current document through the writing Ablo client, validates and applies every step, then uses one confirmed Ablo commit for content/version, accepted steps and an operation receipt. The original captured row guards the commit. A competing edit rejects the stale premise; the client pulls accepted steps and rebases. A retried operation verifies its payload digest against its stored receipt. No stale snapshot overwrites newer content. Metadata updates also guard their captured document; agent names and paper changes check expected values and content version.

Undo/redo emits inverse ProseMirror steps through the same Ablo commit path. Ablo’s `useUndoScope` is not used: serialized rich-text arrays require position mapping rather than field-level snapshot replay. Undo history remains in memory.

Before network transmission, main synchronously stores confirmed base, pending steps and client ID in SQLite with WAL/FULL durability. Saving failure disables editing. Reconnect and restart rebase pending steps using accepted history. Hosted draft databases are scoped by endpoint, organization and verified user. Development drafts use Ablo’s returned organization/project/branch identity. Changing identities cannot upload another account’s draft; key rotation within a branch preserves recovery. Older local-only profiles are left untouched, without automatic import.

The browser synchronously stores the same base, steps and client ID in localStorage before transmission, scoped by service workspace, organization and user. A Web Lock reserves each recovered client so separate tabs cannot replay the same pending operations. A closed tab releases its lock; another tab can recover and rebase its draft after fresh authorization. Quota failure disables editing while keeping existing data. Browser storage has the browser's small per-origin quota and can be evicted or cleared; it is not a backup. A network connection is required to authorize and reopen a document after reload.

The limits are 32 bridge sockets, 16 admitted requests, 1 MiB requests, 256 steps per batch, 2 MB document JSON and a 1,000-document library. Full OT history is retained for offline rebasing; storage grows until acknowledged client horizons and compaction are implemented. Reads use bounded HTTP polling, not a rich-text CRDT or performance claim for large teams.

## Agents and chat

Messages and run records live in Ablo. Sending uses an idempotent message ID with validated sender/intent. Separate processes observe the same transcript. Each authority permits four concurrent agent runs, including several in one document. Every run has its own Ablo actor session. Local Codex runs also have a private MCP token and temporary directory. Hosted runs use the AI SDK with a server-selected provider and model allowlist; direct Anthropic and the provider-neutral gateway use the same document tools. Credentials remain server-side. Hosted generation stops after 12 model steps, 2,048 output tokens per step, or three minutes, without automatic provider retries. Ablo identity and membership are revalidated through the bounded lease before each generation and tool call; stop is checked again at every document commit. The deployment handler registers the run promise with its serverless lifetime owner before returning the chat acknowledgement. Runtime termination leaves an expiring interrupted run; it never replays edits. Expired running records appear interrupted and are never automatically replayed.

Stop marks the document’s running records `stop_requested` in Ablo. Owners poll their run and terminate on stop; every mutating document tool also includes the captured running record in its atomic commit premises. A concurrent stop invalidates that premise. Already accepted edits remain. Unavailable/revoked storage can prevent the final transcript/status write; the run expires rather than fabricating completion.

The UI displays the latest 200 messages. Tool activity is grouped by agent into collapsed readable details. Agent status is above the composer; sync announcements remain available to assistive technology without a visible corner indicator. Hosted message authors use the verified account name. Presence labels are a bounded process-local observation, not global workspace presence. References do not fetch other documents or add prior chat to agent prompts.

## Presentation

The overview/sidebar use the Ablo document index. New documents open Untitled. Shared Pages/Flowing layout is independent of text version. A ResizeObserver scales pages to fit the available width and height. The Decks-derived pagination plugin converts fitted DOM measurements back to paper coordinates and preserves document positions. Flowing removes pagination and retains a white surface. Switching plugins preserves selection and undo history.

`configure_paper` validates all six finite dimensions/margins and usable content area. Invalid/stale updates preserve content and metadata. Pagination breaks between blocks; splitting a single long block across pages is not implemented.

Focused checks: `npm run check`, offline `npm test`, real-service `npm run test:integration`, native `npm run test:electron`, `npm run test:auth`, `npm run test:browser` and `npm run test:desktop`. Native auth checks cover Google/email controls, single browser initiation, PKCE callback, OTP retry, OS encryption and restart against explicitly simulated services. Browser checks cover cookie SSO, two OT clients, shared chat, closed-tab draft recovery and revocation with an in-memory authority. The compiled desktop page check verifies Google initiation, PKCE forwarding, invalid-link refusal and matching callback construction with intercepted provider responses. These checks do not establish fresh Google provider consent. Offline agent checks cover scripted MCP subprocesses and the actual AI SDK loop with explicit model doubles: stale-read recovery, concurrent human additions, argument validation, allowlisted models, cross-authority stop, and sanitized provider errors. `npm run test:agents:live` is a separate explicit real-provider check requiring a disposable Ablo branch and a private trace directory; never point it at production documents.

Hosted runner configuration is server-only: `FORUM_MODEL_PROVIDER` selects `anthropic` or `gateway`, `FORUM_MODEL_API_KEY` supplies that provider credential, and `FORUM_MODELS` is a comma-separated allowlist of exact provider model IDs (first is the default). No configuration means no agent is advertised. Invalid partial configuration fails closed. Model metadata exposes only the allowlisted IDs, never credentials; this is an operator allowlist, not automatic proof that every configured model is available. A serverless integration must supply `waitUntil` to retain run ownership after acknowledgement.

Direct Anthropic acceptance has exercised Claude Sonnet 4.6 and Haiku 4.5 against an isolated hosted Ablo branch: simultaneous agent edits, a concurrent human addition, a real stale-version rejection and model reread/retry, idempotent message retry, shared transcript, and stopping an in-flight generation from another authority. The trace records measured usage for completed provider calls; canceled calls may have no usage result. This establishes the direct Anthropic path; it does not establish live acceptance of another configured provider.
