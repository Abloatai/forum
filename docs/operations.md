# Local operation and recovery

The browser editor at `/app/` shows a loading indicator until its first session check and document-list request finish. The workspace stays hidden during bootstrap; failed requests reveal the normal sign-in or error state. The browser editor reuses the shared Ablo login. Signed-out browser users can open the ordinary shared Google/email sign-in page; Forum resumes once that cookie is available. Browser **Sign out** revokes the shared browser session across Ablo products. Membership revocation still invalidates access within the bounded lease.

The updated native screen offers **Continue with Google** and **Continue with email**. Google opens the system browser and returns through the registered Forum protocol with S256 PKCE; email accepts a six-digit issuer code. These flows require Forum's exact frontend origin and callback scheme in hosted Auth's trusted list. Older downloads can still use the earlier device flow until replaced. The native process encrypts sessions using the OS keychain; a failed or unavailable keychain never causes plaintext token storage. Session expiry or removed membership returns to sign-in. Network failures retain drafts; account authorization is required before opening them again.

For local development, prepare a separate Ablo project using the README commands and keep `.env.local` private. `ABLO_API_KEY` selects explicit project mode. Hosted Ablo owns documents, steps, chat and receipts; the app provides no local backend emulator. Expired branch credentials require the normal Ablo CLI renewal. Temporary hosted test branches expire within 24 hours and must never hold persistent user documents.

Electron stores pending edits under the OS user’s Forum application-data directory. `LOBBY_DOCS_PROFILE` selects an isolated directory. Hosted draft files are bound to endpoint, organization and user; development drafts use the service-returned project and branch. Sign-out closes the active database and hides its records without deleting pending edits. The next authorized sign-in to the same account recovers them. Do not share a profile between unrelated OS users or bypass the single-instance lock.

Edits save locally before transmission. Network interruption preserves pending steps. Keep the window open after a local save failure and resolve filesystem/disk problems. Switching documents saves pending steps locally and restores them when you return. Reopening recovers the first independent draft; additional windows recover additional drafts. Old local-only databases are preserved but are not imported into Ablo automatically.

Close the app before backing up the complete profile. Retain SQLite WAL/SHM files if present. Restore into a separate profile first and verify pending-edit recovery. This backs up local drafts; back up authoritative project data using your Ablo development service’s facilities. Filesystem permissions protect local data; draft files are not application-encrypted. Never commit profiles, databases, credentials or recordings.

Set `LOBBY_DOCS_AGENT_COMMAND` and `LOBBY_DOCS_AGENT_HOME` in ignored `.env.local` to absolute paths for an installed Codex executable and a dedicated, provisioned profile. No profile or model credentials are included. `/model` uses that executable’s catalog. Agents can edit text, name documents and configure paper; each application instance admits up to four concurrent runs.

For a self-hosted Forum API, `FORUM_API_URL` selects its HTTPS origin; loopback HTTP is accepted for local development. Identity and data remain on hosted Ablo. The API implementation owns account validation and workspace isolation; production deployment infrastructure is maintained separately.

The optional agent executable is trusted operator-installed software. Use a dedicated profile. The app does not provision model access. Catalog failure blocks agent requests. Stop retains accepted changes. Interrupted runs expire instead of automatically replaying potentially destructive instructions.

`npm run test:integration` and `npm run test:electron` create synthetic records in the configured development branch. Use a disposable branch with no private documents when recording a demo. `npm run test:auth` and `npm run test:browser` use explicitly simulated services to verify account boundaries and recovery. `npm run make` creates the current Mac package. Optional signing and notarization use an installed Developer ID identity and a keychain profile; no Apple secrets belong in configuration or source. Verify the extracted distributable with codesign, Gatekeeper and stapler, then verify the real hosted handoff and restart before publishing a download. Do not publish a Google/email build before the matching Auth registration is released.

Keep automated chat and editing checks in a disposable development branch or the explicit in-memory fixtures. Production release checks should reuse an authorized session and read existing data; do not post connection-check messages into a user's workspace. If a live mutation is explicitly needed, label its disposable document, record its exact IDs and remove only that test data afterward.

For a disposable verification run without application database setup, Ablo supports explicitly hosted **test** branches with an expiry within 24 hours. Use the CLI’s `branch ensure --kind test --hosted --expires-at ISO_TIMESTAMP` workflow, then push this schema using that branch’s key. Such branches are temporary test data, never a persistent document workspace. An ordinary development project needs its persistent data plane configured separately on hosted Ablo.

The hosted agent loop supports `anthropic` and `gateway` provider configurations described in the architecture document. For real model verification, export the provider configuration, the disposable branch key as `ABLO_API_KEY`, its exact `FORUM_LIVE_TEST_BRANCH` ID, and a private `FORUM_AGENT_TRACE_DIR`; run `npm run test:agents:live`. This check writes synthetic documents in that branch. It records fixture-only model inputs, tool calls/results and measured provider usage for inspection outside Git. A provider 401 indicates rejected credentials; a gateway 402 indicates a billing or credit block. Neither is a reason to substitute another credential silently. Restore the approved connection or balance, then rerun the explicit live check. Provider failures are recorded with model, error name and HTTP status in the private trace; raw headers and provider error bodies are excluded. The browser agent check `npm run test:agents:browser` uses explicitly simulated identity, model and storage.

## Live collaboration verification

`npm run test:agents:live` requires two distinct configured model IDs, a disposable hosted Ablo branch key, its exact `FORUM_LIVE_TEST_BRANCH`, and a private `FORUM_AGENT_TRACE_DIR`. The test checks that the key resolves to that branch before writing. Never use a production branch. The branch's schema must already be active.

The check runs the real provider and document authority. A test-only scheduling barrier pauses each agent after its first read, commits one human's edit, and then resumes both model loops. This makes stale-read rejection reproducible without mocking model responses. Each agent must receive a real stale-version error, reread newer content, and finish its requested edit. A second human's unconfirmed same-paragraph step is then rebased through ProseMirror over the accepted human and agent steps. Both human clients and both authorities must converge to the same document, with the human additions, agent changes and bold formatting retained exactly once.

The same run checks duplicate OT-batch and chat-message retries, messages from two human participants, and stopping an actual in-flight generation from a second authority. Inspect `trace.json` in event order: original user requests, model tool choices, tool results returned in later model context, rejected versions, rereads, confirmed changes, final document and stop. An aborted model call may have no usage result; do not count it as zero usage.

Direct Anthropic verification has passed with Sonnet 4.6 and Haiku 4.5. This establishes the tested OT/guarded-write paths, not a CRDT, exclusive resource claims, arbitrary conflicting editing intent, or production-scale performance. The separate live Ablo check in `tests/ablo.test.ts` exercises atomic competing commits through independent authorities; its agents are explicitly scripted rather than real models.

## Coverage and concurrency checks

Run `npm run test:coverage` on Node 24. It uses Node's built-in coverage reporter and enforces floors of 90% lines, 80% branches and 80% functions for source loaded by the Node test suite. No coverage package or private credential is required. The source include pattern excludes test fixtures and dependencies. This is not an application-wide percentage: browser modules, Electron entrypoints, deployment handlers and unimported source do not enter that report. Their behavior is checked separately by the browser, native and deployment suites. Generated reports and private traces belong outside Git.

The offline suite includes focused personal-account isolation and revocation checks. Coverage output reports the current loaded-source result; the application-wide exclusions above still apply. These are observed results, not a claim of full coverage. The tests cover overlapping agent replacements, lost commit responses with durable receipt recovery, Stop racing a document commit, model-step limits, pending authorization limits, delayed identity proofs, unsafe vaults, malformed RPCs and transient server errors. The concurrency fixture checks 12 ProseMirror clients, 96 competing edits and repeated disconnects through the actual WebSocket bridge with simulated Ablo storage. A committed-but-lost response is injected; clients pull confirmed history before retrying, matching the editor’s recovery flow.

Both Anthropic and gateway SDK adapters also execute the same read/edit/confirmation sequence against synthetic HTTP responses. Optional `FORUM_AGENT_TRACE_DIR` writes fixture-only protocol traces outside Git for inspection. These protocol checks do not establish live availability, billing or performance of another model provider.

For the real hosted Ablo concurrency check, prepare a disposable test branch with this schema, then set `ABLO_API_KEY`, its exact `FORUM_LIVE_TEST_BRANCH` and a private `FORUM_AGENT_TRACE_DIR`. Run `npm run test:concurrency:live`. It refuses a root branch ID or mismatched key, opens three independent native authorities and 12 OT clients, and verifies 48 competing edits plus reconnects. `concurrency.json` records request/response metadata, transport errors, the canonical synthetic document, conflicts, duration and convergence result; failures also retain a trace. The driver recovers known transport failures by pulling history before retrying and fails on other errors or its bounded progress budget. It makes no model calls. Delete the disposable branch afterward. This bounded workload is a regression check, not a production capacity or latency guarantee.

Run the compiled UI suites separately: `npm run test:browser`, `npm run test:desktop`, `npm run test:site`, `npm run test:agents:browser` and `npm run test:auth`. Their simulated boundaries are stated in the test output. No line/branch coverage is currently aggregated across browser and Electron processes. Real Google consent, OS variants, long-running large-team load and every possible editing intent are outside these checks.

A real hosted run of that bounded workload converged to version 48 with all 48 markers exactly once: 386 version conflicts, 24 planned disconnects and 12 recovered unknown outcomes over 64.327 seconds. This checks recovery under contention; it does not establish fast large-team editing or an SLO.

## Personal Codex accounts

The hosted API uses the signed-in member's personal ChatGPT connection. Forum sign-in and model access are separate: after Google/email sign-in and workspace selection, onboarding requires connecting a personal ChatGPT/Codex account before continuing. Failed or canceled approval keeps setup open and allows retry. Already connected accounts skip this step. After completing setup, open Account → Codex account to connect or disconnect; disconnected members can still edit documents and chat with humans, but cannot launch agents. Setup completion is local to that browser/device, so a new device without a connection asks again. Older optional-skip preferences do not count as completed connection setup. A shared document does not share a member's model credential. Existing shared provider environment variables do not enable inference in this API.

`src/codex` owns the connection. It follows Coding's native Codex App Server device-code flow with pinned `@openai/codex` 0.153.0. The server opens a separate temporary home, inherits no API keys or parent Codex login, and accepts only ChatGPT account authentication. The browser receives the device code, approval URL and public account/model metadata. Approval must finish within four minutes. Pending approval runs under the server's background-work lifetime; a killed process requires retrying sign-in.

Credentials live in the server-only `forumCodexConnections` Ablo model, encrypted with AES-256-GCM. The record ID hashes the authenticated user ID; authenticated additional data binds ciphertext to that ID. Human and agent Ablo sessions receive no permission for this model. `FORUM_CODEX_ENCRYPTION_KEY` must contain 64 hexadecimal characters and stay in private server configuration. The authority's administrators and runtime remain trusted. Keep a private backup: replacing this key without re-encrypting stored records makes existing connections unreadable. Never put the key or account records in Git, browser storage, document tools, logs or transcripts.

Each run binds the credential generation to its initiating member. The account is rechecked before tools and during the run. Disconnect changes that generation, rejects further work, and cannot be undone by a delayed login completion or refresh. A conditional Ablo lease serializes token refresh between server instances. A failed refresh requires reconnecting; it never falls back to a shared key. A run's temporary login is removed afterward. Already submitted model requests or confirmed document edits cannot be recalled by disconnect.

Runtime requirements are hosted Ablo with this schema, the private encryption setting, the pinned native Codex executable, and outbound OpenAI access. `FORUM_CODEX_COMMAND` can select an absolute executable location when packaging the server. Login and inference processes need their own bounded background lifetime. The production publication recipe and infrastructure remain outside this public repository. Local native-agent configuration and explicit provider-adapter tests remain independent of the hosted personal-account route.

Run `npm run test:pages` for actual compiled-editor pagination, viewport stability, focus feedback and personal connection controls with explicitly simulated issuer, storage and approval. Unit checks in `tests/codex.test.ts` cover isolated native-process transport, encrypted storage, member isolation, revocation, refresh and stale writes. A real provider approval and successful inference are separate acceptance checks; mocked approval is not proof of either.

## Page layout and focus

Paged mode draws white sheets with a full-width gutter at each configured page height. Paper size and margins still come from shared document metadata. Pagination measures edited blocks before paint, reuses unchanged geometry and does not reset when only display zoom changes. The canvas reserves scrollbar space and does not automatically scroll back to the selection on resize. Clicking blank paper focuses the document; the toolbar shows Editing while the text editor has focus, without adding a border around the text. Flowing mode remains white and has no pagination widgets. Oversized individual blocks are still not split across pages.

After the up-to-date poll began skipping its redundant history read, one repeat of the same real Ablo workload converged in 46.829 seconds (12 clients, three authorities, 48 edits, 24 reconnects, 400 version conflicts, no transport recoveries). The earlier run took 64.327 seconds and recovered 12 unknown transport outcomes. These runs have different network/recovery timing; they do not isolate a causal speedup or establish an SLO. Contention still produces many retries.


## Workspace access

Use Members to invite a collaborator, accept a pending invitation, switch workspace or create one. Owners/admins can send or cancel invitations. A new account must choose or create a workspace before opening documents. Invitations initiated by production Forum return to its editor after shared Auth is registered with that route. An expired, canceled or wrong-recipient invitation grants no access. Auth failures keep the invitation form available for retry and never infer membership locally.

Share copies a link for existing workspace members. All workspace members can access all its Forum documents, and the membership is shared across Ablo products. There are no public or document-specific grants. Removing someone through the shared Auth members interface revokes future access within the short authorization lease; it does not erase an offline copy already held on their device. Changing workspaces preserves pending drafts under the previous account scope.

Run `npm run test:members` for the compiled members/onboarding UI with two simulated users and storage. `tests/members.test.ts` checks server trust boundaries, stale-workspace recovery and fresh workspace selection. Shared Auth release verification is maintained in that service's test documentation, not in the public Forum deployment setup.
